> **Ultra-fast, Zero-ORM, Injection-Safe Text-to-SQLite Stream Parser in Bison/C.**

`sql-sanitizer` is a minimalist, single-binary streaming parser designed to transform massive volumes of raw, untrusted text streams into safe, highly optimized SQLite transaction batches.

By bypassing heavyweight runtimes (Python, Node.js) and ORM overheads, it enables direct piping of scraped text, application logs, and NLP raw corpora into the `sqlite3` CLI at native I/O speeds—with mathematical certainty against SQL injection.

---

## Why `sql-sanitizer`?

In traditional data engineering pipelines, inserting millions of unstructured documents into SQLite typically involves:
1. Parsing documents in a high-level language (Python/Node).
2. Constructing ORM objects or parameter bindings.
3. Dealing with memory overhead, connection pooling, and GC latency.

When importing high-throughput streams (e.g., crawler dumps, syslog firehoses), this creates severe CPU and memory bottlenecks.

```
[ Traditional Pipeline ]
Raw Stream ──▶ [ Python Runtime / ORM ] ──▶ [ SQLite Driver ] ──▶ Disk
               (High Memory, GC Stalls, Slow Throughput)

[ sql-sanitizer Pipeline ]
Raw Stream ──▶ [ sql-sanitizer (Bison/C) ] ──▶ (pipe) ──▶ [ sqlite3 CLI ] ──▶ Disk
               (Sub-megabyte RAM, Zero-Copy Escaping, Wire Speed)
```

`sql-sanitizer` adheres strictly to the **Unix Philosophy**: do one thing, do it right, and communicate via plain-text streams.

## Key Features

- **100% Injection-Proof by Design**:
  - Automatically neutralizes single-quote (`'`) boundaries using SQLite-standard doubling (`''`).
  - Strips binary control characters (`\x00`–`\x1F` except standard whitespace) to eliminate NUL-byte poisoning.
  - Transparently preserves multi-byte UTF-8 sequences across international scripts.
- **Extreme Throughput**:
  - Automatically emits `PRAGMA journal_mode = WAL;` and `PRAGMA synchronous = NORMAL;` headers.
  - Groups inserts into automatic `BEGIN TRANSACTION; ... COMMIT;` batches (1,000 records per transaction) to maximize disk write efficiency.
- **Zero External Dependencies**:
  - Self-contained Bison parser with an integrated DFA lexer.
  - No Flex required, no external libraries, no database client SDKs.
- **Sub-Megabyte Memory Footprint**:
  - Operates strictly in constant streaming memory ($O(1)$ dynamic buffer reallocation).
  - Can be deployed inside minimal containers, Alpine Linux, or embedded edge nodes.

## Document Specification (Input DSL)

The parser accepts structured document blocks enclosing arbitrary raw text bodies:

```text
Document(id: "doc_001", lang: "en", category: "crawler_output") {
    Here is raw untrusted text with single quotes ('hello') and strings like
    '); DROP TABLE raw_corpus; -- which are treated 100% as string literals.
}

Document(id: "doc_002", lang: "ja", category: "customer_feedback") {
    日本語の生テキストも安全にエスケープされ、SQLite に直接流し込まれます。
}
```

### Attributes
- `id`: Unique document identifier (string literal).
- `lang`: Language code (ISO 639-1 recommended, e.g., `"en"`, `"ja"`, `"zh"`).
- `category`: Domain tag or extraction source label.

## Target Database Schema

`sql-sanitizer` automatically emits DDL initialization headers, creating the following schema on the fly if it does not already exist:

```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;

CREATE TABLE IF NOT EXISTS raw_corpus (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    doc_id TEXT,
    lang TEXT,
    category TEXT,
    raw_text TEXT,
    created_at DATETIME
);
```

## Installation & Build

Requires only `bison` (GNU Bison 3.0+) and a standard C compiler (`gcc` or `clang`).

```bash
# Clone repository
git clone https://github.com/your-username/SQL-sanitizer.git
cd SQL-sanitizer

# Build executable
bison src/sql_filter.y -o src/sql_filter.c
gcc -O3 src/sql_filter.c -o bin/sql_filter
```

## Usage Examples

### 1. Direct Pipe to SQLite
Stream input text directly into your database file without intermediate dump files:

```bash
cat input_documents.txt | ./bin/sql_filter | sqlite3 corpus.db
```

### 2. Inspect Sanitized SQL Stream
You can inspect the generated SQL statements directly on standard output:

```bash
./bin/sql_filter < input_documents.txt | head -n 30
```

Sample output:
```sql
-- Auto-generated by UBS sql_filter (Injection-Safe Pipeline)
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
CREATE TABLE IF NOT EXISTS raw_corpus (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    doc_id TEXT,
    lang TEXT,
    category TEXT,
    raw_text TEXT,
    created_at DATETIME
);
BEGIN TRANSACTION;
INSERT INTO raw_corpus (doc_id, lang, category, raw_text, created_at) VALUES ('doc_001', 'en', 'crawler_output', 'Here is raw untrusted text with single quotes (''hello'')...', datetime('now'));
COMMIT;
```

### 3. High-Volume Compression Pipeline
For bulk archive compression:

```bash
cat large_crawl.txt | ./bin/sql_filter | gzip -c > sanitized_corpus.sql.gz
```

## Security Model

`sql-sanitizer` enforces strict boundary isolation:
1. **Quote Escaping**: Every single quote (`'`) inside `{ ... }` is transformed to `''`. In SQLite's SQL grammar, `''` within string literals unambiguously represents an escaped single quote and cannot break out of the string boundary.
2. **NUL Injection Mitigation**: `\0` bytes are dropped from the stream to prevent C-string truncation attacks.
3. **Control Code Sanitization**: ASCII control bytes below `0x20` (excluding `\n`, `\r`, and `\t`) are transformed into benign spaces, preventing terminal escape poisoning and driver malfunctions.
